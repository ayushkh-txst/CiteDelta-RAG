# ADR-0005 — Local embeddings first, hosted adapter second

**Status:** Accepted · **Date:** 2026-08-08

## Context

The next deliverable is a reproducible recall benchmark: brute force → IVF-Flat
→ HNSW, with recall@10 vs. an oracle. Reproducibility is only meaningful if the
same query returns the same embedding every run.

## Decision

Run embeddings **locally** via `fastembed` + `BAAI/bge-small-en-v1.5`
(384-dim, ONNX). Define an `EmbeddingProvider` port behind it and implement a
hosted adapter *later*, purely to prove the port is real.

## Alternatives

- **Hosted API (OpenAI, Cohere, …)** — higher-quality vectors, but the model
  silently changes version, so one run's recall number would not be comparable
  with the next. Cost is nonzero.
- **Bigger local model** — higher quality, but heavier to ship and npm slots
  cost money upstream; the sweep exists to quantify, not to win.

## Consequences

**Positive.** Deterministic, offline-capable, honest cost = $0, and the
benchmark itself is machine-reproducible. The adapter proves the port actually
has an interface.

**Negative.** bge-small is weaker than a frontier embedding model; Section 9 (the
"what would be deployed" section) must quantify that gap rather than assume it.
