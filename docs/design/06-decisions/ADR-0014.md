# ADR-0014 — RRF over score normalization

**Status:** Accepted · **Date:** 2026-08-11

## Context

Lexical BM25 scores are unbounded and corpus-dependent; semantic cosine
similarities are bounded to [-1, 1]. Fusing the two retrievers requires mapping
them onto a common scale, and the obvious answer — normalize both — quietly
destroys information: a query with one strong hit and ten mediocre ones
normalizes identically to a query with eleven strong hits.

## Decision

Fuse on *ranks* using reciprocal rank fusion (Cormack, Clarke & Büttcher 2009):

```
score(hit) = Σ_r 1 / (k + rank_in_r)
```

with `k = 60`. Each retriever contributes a ranked list of candidate chunk ids;
the fused list is re-ranked and returned with per-retriever provenance attached
(`[lexical#n vector#m]`) so any answer can be audited.

## Alternatives

- **Min-max score normalization** — destroys confidence information; one strong
  match and ten mediocre ones normalize identically to a uniformly strong
  result. Rejected.
- **Z-score** — assumes a score distribution the scores don't have, and the
  mean/std shift with the corpus, re-fitting on every rebuild. Rejected.
- **Fixed weights** — a constant fitted to the eval set that won't transfer and
  reopens calibration on every corpus change. Rejected.

## Consequences

**Positive.** No calibration constant anywhere; scale-free across corpora and
embedding models; order-invariance of the retriever fusion is property-tested
(any permutation of the per-retriever lists yields the same fused ranking).
Provenance on every row makes retrieval auditable.

**Negative.** Absolute score magnitude is discarded, so RRF cannot express
"neither retriever found anything good" — that has to come from a separate
confidence gate. `k=60` is inherited from Cormack et al. and **has not been
re-tuned on this corpus**, deliberately: tuning it against ~60 eval cases
would fit noise.
