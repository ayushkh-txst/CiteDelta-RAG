# ADR-0009 — Tie-aware recall is the headline metric

**Status:** Accepted · **Date:** 2026-08-09

## Context

The corpus has 38,211 chunks but only 1,759 distinct vectors (21.7× duplicate
ratio): CFR text is formulaic and repeats across versions, so exact duplicate
vectors are everywhere. A naive id-based recall scores even exact search below
1.0 against its own ground truth when ties break differently, which would send
you debugging a correct index.

## Decision

Recall is measured on distances, not identities. A result counts if its
distance is within the k-th ground-truth distance plus `TIE_EPSILON = 1e-5`.
Both numbers are published: tie-aware `recall` and `recall_by_id`, so the gap
remains visible as a measure of corpus duplication.

## Alternatives

- **Id-based recall only** — brute-force search scores 0.999 against itself;
  IVF at perfect tie-aware recall scores 0.34 by id. Wrong conclusions.

## Consequences

**Positive.** The metric doesn't care how an index breaks an exact tie, so it
measures retrieval quality rather than tie-breaking luck. The gap between the
two published numbers is itself a finding — it is why even exact search reports
<1.0 under the naive metric.

**Negative.** A tolerance is a judgment call. Too large a value would forgive
genuinely worse results; 1e-5 is stated and constant. And the tie-aware number
can run far above the id number enough to invite the "is 1e-5 doing the work?"
question — which is exactly why both are always reported and the tolerance is
stated.
