# ADR-0008 — `effort` instead of `ef` in the vector protocol

**Status:** Accepted · **Date:** 2026-08-09

## Context

The spec sketches `search(q, k, ef=None)`, which leaks an HNSW-specific
parameter into an interface that IVF and brute force must also implement.
Each index trades accuracy against speed with a different knob — `nprobe` for
IVF, `ef_search` for HNSW, nothing for brute force — but every index has
exactly one such knob.

## Decision

The protocol names the concept: `search(query, k, *, effort=None)`,
keyword-only. Each implementation interprets `effort` in its own units. The
brute-force index ignores it (`None` in the benchmark sweep).

## Alternatives

- **`ef` as the parameter name** — bakes one implementation's terminology
  into an interface three implementations must share; IVF would inherit a
  name that means nothing to it.
- **No knob in the protocol** — the benchmark could only sweep each index by
  reaching into its guts, defeating the purpose of the shared interface.

## Consequences

**Positive.** The benchmark harness sweeps every index with one loop of
`effort` values; the conformance suite uses it to demand exactness at
"maximum effort" from approximate indexes.

**Negative.** `effort=64` means different things per index, so a benchmark
row is meaningless without the index name next to it. Every table in
`03-benchmarks.md` therefore carries the index column, and the recall-vs-QPS
plot marks each index with its own marker.
