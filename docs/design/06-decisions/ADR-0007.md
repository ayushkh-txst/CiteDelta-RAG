# ADR-0007 — Three vector indexes behind one protocol

**Status:** Accepted · **Date:** 2026-08-09

## Context

The project's thesis is a graded ladder: each retrieval structure is shipped
independently and measured against the one below it. That requires one
interface every implementation can satisfy.

## Decision

Every vector index implements the same `VectorIndex` protocol
(`build`, `search`, `save`, `load`, `name`, size/dimension properties). Three
implementations: brute force (the oracle), IVF-Flat, HNSW. A single
conformance suite (`test_index_conformance`) is parameterized over the
factories; any index that cannot run the suite unchanged does not exist.

## Alternatives

- **One index doing double duty, prototypes only** — no measurements, no
  oracle, nothing to whiteboard.

## Consequences

**Positive.** Three implementations to maintain, but one suite keeps them
honest and each new index costs three lines to join. Brute force stays in the
product permanently as the correctness oracle — exact recall on demand is a
feature, not dead code, and it is what makes tie-aware ground truth computable
at all.

**Negative.** Three implementations to benchmark, build, and persist. The
conformance suite grows as invariants are discovered. The brute-force oracle
has to exist forever for the other two to keep a ground truth to be measured
against.
