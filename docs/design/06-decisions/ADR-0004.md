# ADR-0004 — Bitemporal at section granularity, with a GiST exclusion constraint

**Status:** Accepted · **Date:** 2026-08-08

## Context

The corpus has real data with both temporal axes: `issue_date` (when eCFR
recorded the amendment) and `amendment_date` (when it took effect). 34 records
in 8 CFR Part 214 have a genuine gap between them. Storage must keep both and
must not allow two versions to claim the same validity interval.

## Decision

Model valid time and transaction time at **section-version** granularity, with
both intervals stored `daterange`-typed and a GiST `EXCLUDE USING gist
(daterange … WITH &&)` constraint guaranteeing a section has non-overlapping
validity.

## Alternatives

- **Chunk-granularity bitemporality.** Finer, but eCFR reports change at
  section level; any finer granularity invents precision the source lacks.
- **No constraint, enforce in code.** The invariant becomes conventional
  instead of structural; a bug in one upsert path silently overlapped two
  versions.

## Consequences

**Positive.** The database makes overlapping validity *impossible* rather than
merely discouraged. `as_of` queries are a single indexed range-overlap. Sections
inherit the exclusion constraint implicitly when chunks are keyed to their
section-version.

**Negative.** Requires the `btree_gist` extension. The write path is slightly
slower and an overlap conflict must be translated into a meaningful error. The
half-open `[from, to)` convention means every boundary check must remember that
`to` is exclusive (this actually keeps size-insoluble bugs, like a gap, out of
the model).
