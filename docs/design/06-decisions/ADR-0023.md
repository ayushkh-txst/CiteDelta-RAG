# ADR-0023 — OpenRouter for both the answer model and embeddings

**Status:** Accepted · **Date:** 2026-08-23

## Context

The project needs to run on infrastructure that costs $0 and needs no credit
card, so it can be hosted and demoed freely. Two things stood in the way:
Anthropic billing for the answer/resolver models, and `fastembed` — the local
ONNX embedding path from ADR-0005 — whose ~200MB model download and
onnxruntime dependency push a container well past a free-tier image budget.

Routing both through one OpenRouter key, with one API surface and one bill,
removes both blockers at once and lets the app run on a free host against a
free Postgres (Supabase). The original target host was Hugging Face Spaces;
HF changed Docker Spaces to a paid-only feature in August 2026 (free accounts
get Static/Gradio only, neither of which fits this app), so the app itself
runs on Render instead — see [docs/deploy/free-hosting.md](../../deploy/free-hosting.md).
That change is about where the container runs, not this ADR's decision.

## Decision

- **Answer + resolver models**: `google/gemma-4-26b-a4b-it:free` via a new
  `OpenRouterCompletions` adapter (`substrate/llm/openrouter_adapter.py`),
  implementing the existing `Completions` port unchanged. Provider selection
  is config-driven (`llm_provider`) through `substrate/llm/factory.py`, so
  Anthropic remains available as a fallback.
- **Embeddings**: `openai/text-embedding-3-small`, truncated from its native
  1536 dimensions to **512** and renormalized (`OpenRouterEmbeddings`,
  `citedelta/embed/openrouter.py`), implementing the existing
  `EmbeddingProvider` port. This **supersedes ADR-0005's local-embeddings
  decision** — determinism is no longer the binding constraint; free hosting
  is. `LocalEmbeddings` stays in the tree as an opt-in path for the recall
  benchmark, where reproducibility still matters.

512 dimensions, not the full 1536: ~38k chunks at 1536-dim would be ~233MB of
raw vectors, most of a free 500MB Postgres budget before section text and
indexes. At 512 it's ~78MB. text-embedding-3-small is Matryoshka-trained, so a
leading prefix is independently meaningful — truncate-then-renormalize is a
quality trade, not noise.

## Alternatives

- **Keep Anthropic, only move embeddings** — doesn't solve the actual
  blocker (Anthropic billing on a $0 deployment) and leaves two vendor keys
  instead of one.
- **Full 1536-dim embeddings** — best quality, but doesn't fit the free
  Postgres tier without aggressively pruning the corpus. Rejected for this
  deployment; revisit if a larger free tier or a paid tier becomes available.
- **A free embedding model (e.g. NVIDIA Nemotron 3 Embed, $0 on OpenRouter)**
  — genuinely free, but untested against this corpus's recall numbers.
  Deferred rather than rejected: worth benchmarking before committing.

## Consequences

**Positive.** One key, $0 baseline cost, and a container light enough for a
free host. The provider abstraction added in ADR-0005 and the `Completions`
port both paid off exactly as intended: neither `AnswerService`,
`resolve_followup`, nor the retrieval/index code needed to change.

**Negative.** `google/gemma-4-26b-a4b-it:free` is a 26B model behind
Anthropic's `claude-opus-5` — the citation validator will reject more
answers, and that gap needs measuring against the existing recall benchmark
rather than assumed away. The `:free` tier is rate-limited (50 requests/day
until $10 of lifetime credit is purchased, then 1,000/day), which caps a live
demo at roughly 25 turns/day. `text-embedding-3-small` is not itself free
(~$0.02/M tokens) — the corpus re-embed and steady-state query cost are both
small, but "free" here means the LLM, not every model on the path.
