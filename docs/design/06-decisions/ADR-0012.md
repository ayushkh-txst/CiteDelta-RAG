# ADR-0012 — Traverse through inadmissible nodes; filter only the result set

**Status:** Accepted · **Date:** 2026-08-11

## Context

The obvious implementation of a filtered HNSW search prunes the walk: do not
enter inadmissible nodes. At 1.91% selectivity, `M0 = 32` neighbours × 1.91%
≈ 0.6 admissible neighbours per node. The admissible-only subgraph has mean
degree 1.04, 72% of admissible nodes are fully isolated, and the largest
admissible-only component is 17.4% of admissible nodes — measured on the built
38,211-node graph. A walk restricted to admissible nodes caps recall near 0.17
at *any* `ef`, because ~83% of admissible nodes are unreachable from any
starting point.

## Decision

Traversal is **never** filtered. The search walks the full graph exactly as an
unfiltered search does; the filter applies only when a candidate is promoted
into the result set. Hitting a bond to an inadmissible node is fine — traverse
it, and simply discard the result if it cannot be an answer. The upper-layer
descent is also unfiltered, since its only job is navigation toward the layer-0
region. The same reasoning applies to IVF: probing is unfiltered; only accepted
results are filtered.

## Consequences

**Positive.** Recall@10 at 1.91% selectivity: 0.484 (HNSW), 0.949 (IVF-Flat)
where pruning would cap near 0.17. Inadmissible nodes are the bridges, so the
index spends a little extra work to keep the graph searchable.

**Negative.** The search cannot terminate the moment it holds k candidates if
some are inadmissible — the stopping rule must keep exposing candidates until
`ef` *admissible* neighbours are held or the budget runs out. That cost is
unbounded for a pathological filter, which forces ADR-0013. The remaining gap
between HNSW pushdown (0.484) and IVF/brute (0.949/1.000) is this corpus'
reachability ceiling, corroborated by the `hnswlib` oracle (ADR-0010): HNSW
cannot reach every true nearest neighbour here, filtered or not.
